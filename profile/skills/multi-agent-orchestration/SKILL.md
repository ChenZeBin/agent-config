# 多智能体编排

遵守全局 AGENTS.md 的常驻启动核与安全核。仅由主智能体使用本 Skill；子智能体直接完成获派任务，不递归派发。

## 派发判断与数量

- 对非简单任务，主智能体先判断分支是否具有独立交付价值，再选择角色。按新增分支的收益、协调成本、写入隔离和主控整合能力决定数量，不设人为固定上限；不得超过当前实际运行时容量。角色匹配本身不构成派发理由。
- 研究、代码库探索、测试定位、方案设计、审查、验收，以及写入范围互不重叠的实现，优先派发。
- 主智能体保留整合依赖最强、最需要全局上下文或最终判断的关键路径，不重复执行已派发工作。

## 角色路由

| 角色 | 当前本机模型 / effort | 主要交付与边界 |
| --- | --- | --- |
| `explorer` | Luna / max | 明确范围内的文件、符号、配置、字段定位与清点，已知来源定向查询；结论可由路径、行号或原文直接检查，只读 |
| `investigator` | Terra / high | 只读追踪分支、状态、异常/重试路径，分析实现与文档差异、多个来源的冲突和适用条件；交付证据链，不作审查裁决或方案取舍 |
| `worker` | Terra / high | 边界明确的实现、修复和针对性验证；仅修改明确分配的范围 |
| `acceptance_tester` | Terra / high | 按已确认需求和标准执行功能、UI 或端到端验收，输出真实操作证据；不修复、不自行降低通过门槛 |
| `strategist` | Sol / max | 架构、产品、流程、选型、优先级、资源、成本、风险与验收标准设计；提供可审查建议，不实现、不替用户授权 |
| `challenger` | Sol / high | 只读审查代码、方案或标准，寻找可复现缺陷、错误假设、遗漏、反例和高代价风险；不负责实现 |
| `default` | Terra / high | 边界明确的非代码文档、报告、表格、演示稿等产物制作与转换，以及不属于以上专门角色的通用任务；使用适用 Skill，不得绕过专门角色边界 |

- 按当前主要交付物选择角色，不要求固定流水线。
- 路由看推理结构和错误后果，不只看文件数量：简单跨文件调用者清点可给 explorer；需要解释分支、状态变化、失败原因或来源冲突时给 investigator。发现问题并不自动等于审查；安全/质量/发布裁决由 challenger 或主控负责，方案与验收标准设计由 strategist 或主控负责。
- 主控默认使用 GPT-6 Astra / medium（中），保留最终整合、关键事实核验与高风险决策。Terra 是复杂调查的试验路由，尚无足够对照证明全面优于 Luna；调整时用相同输入、工具权限和验收标准比较，分别记录事实错误、关键遗漏、证据不支持、环境失败、耗时与实际可取得的消耗，不把少量样本当总体正确率。
- 以上是本机配置。派发前以当前工具可用角色和角色文件为准；角色文件固定的 model/effort 优先，不能靠 spawn 参数把 explorer 临时变成 Terra。新角色未出现在工具中时核验配置加载，由当前主控接管该分支，不静默降回不适任角色。
- 区分只读职责与实际权限隔离：角色文件的 `sandbox_mode` 是默认值，父回合的实时权限覆盖可能优先应用。仅当任务依赖强制隔离时核验生效的 sandbox/approval 与工具权限；不能只凭角色文件宣称已隔离，也不擅自改变用户的权限设置。
- `challenger` 可在高风险方案实施前、代码合入前或发布前介入。
- 主要交付物超出原角色职责时，应结束原任务并重新路由；角色职责内的必要辅助步骤不算越权。

## 按需阶段交接

- investigator 需要编写或构建隔离复现程序时，交回假设、输入、环境与复现条件，由主控或 worker 在指定临时范围实现和运行；必要时再交 investigator 分析证据。
- strategist 设计验收标准后由主控确认，acceptance_tester 按标准执行；主控可承担已有能力覆盖的阶段，不为形式完整强制串联角色。
- worker 自测属于实现证据。同一实现者换回合或提示词不能成为独立审查者；需要独立审查时使用未参与该实现的审查者，绑定被审版本，相关修改后重新核验受影响证据，沿用适用的 evidence-gate。
- challenger 提供审查意见，由主控核验并形成采用或发布判断。对会改变决策的重要发现简述采纳、经证据驳回或仍未解决及依据；审查标签本身不构成新增用户确认要求。

## 派发契约

- 每份派发提示词必须使用最小完备上下文，明确角色及选择理由、目标与范围、读写边界、约束、交付物，以及核验证据或验收标准；仅在影响边界时补充非目标。
- 涉及状态变更时传递已有授权及其适用环境、目标和动作范围；仅在影响边界时列明账号、载荷、次数或额度。授权不得因派发而扩大，也不重复索取。已授权但缺能力的步骤由主控承接或重新路由，保留实际执行者与证据范围，不冒充单个角色独立完成全流程。
- 任务名称应反映具体交付物，不得用模糊名称代替角色和范围判断。
- 优先使用 `fork_turns="none"`；提示词必须自包含。只有关键上下文无法无损压缩时，才继承最少量的近期对话。
- 子智能体应返回可核验依据，例如文件与行号、来源链接、测试命令与结果、复现步骤、截图或风险清单。
- 取证任务说明需要回答的事实、已知范围与关键字段。代码附 revision 或 working tree 状态；网页附原始 URL、相关日期/版本与访问时状态。精确转录保留原值，规范化值另列依据；证据不足时标注不确定，不能猜测补齐。

## 执行中增量派发

- 执行中发现新的独立分支时可增量派发。

## 证据核验与汇总

- 主智能体逐项回到原始证据核验会改变实现、发布、安全或架构决策的关键事实；非关键事实可抽查。只核验关键断言及其适用条件，不重复完成整个分支。
- 区分事实、推断、来源观点与未知项；“未找到”受搜索范围限制。区分模型判断错误、环境不可访问和任务中断，不以最终报告存在或任务结束推断正确、完整或验收通过。
- 收集必要结果后，由主智能体统一汇总完成情况、验证结果和剩余风险。
