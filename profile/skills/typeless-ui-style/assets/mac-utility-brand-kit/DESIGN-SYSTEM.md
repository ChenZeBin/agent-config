# Mac 小工具家族设计规范 v0.1

建议采用「母品牌背书＋可区分的产品图标＋原生 macOS 交互」。目标是让用户看出同一发行者，同时能迅速找到需要的工具。公司名尚未提供，当前交付是无字母名依赖的符号概念与可复用规范，产品名称也仅作示例。

## 1. 选型与适用范围

| 路线 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 每个 App 完全相同 Logo，只换颜色 | 制作快 | 单色模式、Dock 与菜单栏中易混淆 | 不采用 |
| 每个 App 独立品牌 | 单品表现充分 | 量产时设计、网站和文案维护成本高 | 留给旗舰产品 |
| 同一母品牌，产品共享图形语言 | 可复用、能区分、可持续扩展 | 需要维护一份规范 | 推荐 |

网上参考依据见 [sources.md](sources.md)。Apple 要求与本公司的建议数值明确分开：下述间距、尺寸和配色都是本方案起点，不是 Apple 强制常量。

## 2. 母品牌与 Logo

主推概念 01「榫合」：相互配合的几何构件，表达多个小工具组成一套。概念 02 是 utility 的 U 折带，概念 03 是机械小鸟。推荐 01 是因为不绑定行业、语言或尚未确定的公司名；02 更直观但较通用，03 更有性格但可能抢过工具本身。

- 母标使用 `logos/brand-mark.svg`；浅色背景用深墨，深色背景用 `brand-mark-inverse.svg`。不加阴影、描边、倾斜或拉伸。
- SVG 画布已有留白，外侧再保留至少可见符号宽度 1/4 的保护区；文字和其他标志不得侵入。
- 普通品牌露出建议可见符号至少 24pt。16px 仅用于 favicon/小尺寸识别预览；不要把母标作为所有工具相同的菜单栏图标。
- 官网头部、关于页、首次欢迎页、帮助页页脚使用同一母标。工作区不常驻大 Logo；不增加品牌启动等待页。
- 公司名称确定后，字标放在母标右侧，间距约母标可见宽度 1/3。正文与字标分开维护，不把未确认名字写入图形。
- 关于页统一：产品图标 → 产品名 → 版本 →「由 {品牌名} 制作」＋母标 → 支持 / 隐私 / 更多工具。
- 不声明已完成商标查重。当前 SVG 是新制作设计稿，商业定稿仍需名字和视觉方向确认。

## 3. 图标家族

公司 Logo、App 启动图标、菜单栏图标分为三种资产。母标负责发行者识别；App 图标负责功能识别；菜单栏图标负责快速操作和状态。

App 图标使用统一居中构图、实色几何、相同粗细与圆角语法。家族的共同细节是小型断开构件/切口与平整色块，不强制把完整母标缩进角落。三个示例是便笺、计时、文件夹；真实产品先选择一个唯一功能隐喻。

| 固定项 | 可变项 |
|---|---|
| 图形视觉重量、前景占画布约 55–65%、无文字、轮廓清晰 | 中心图形、一个产品强调色 |
| 前景原始 SVG、不烘焙平台特效 | 前景必要的层次拆分 |
| 16/32/64 尺寸都检查；Mono 下轮廓仍可区分 | 经检查后微调内部细节 |

预览文件 `logos/family/*.svg` 含圆角底板，仅用于设计评审。`logos/layers/*.svg` 是没有底板的前景层起点。发布当前 macOS 图标：按 Apple 当前模板使用 1024×1024 布局，导入未蒙版图层到 Icon Composer，设置背景与材质，检查 Default/Dark/Mono 对应外观，再集成 Xcode。不要把预览圆角再次送给系统蒙版。要兼容旧系统时，按实际 Xcode/部署目标配置对应 asset catalog；本次没有生成 `.icon`、`.icns` 或应用包，也没有验证 Dock 效果。[Apple 图标指南](https://developer.apple.com/design/human-interface-guidelines/app-icons)、[Icon Composer](https://developer.apple.com/icon-composer/)。

菜单栏使用各产品功能符号的专用简化单色版本，按 template image 方式适配系统；建议从 18pt 光学尺寸检查。不能机械缩小彩色 App 图标。录音/暂停/离线状态同时提供文字或可访问名称，不能仅靠颜色。

## 4. 视觉变量

| 类别 | 建议 |
|---|---|
| 品牌基础 | 深墨 `#17252A`；纸白 `#F6F7F3`；强调青绿 `#167D8D` |
| 产品图标示例色 | 便笺青绿 `#167D8D`、计时赭橙 `#A64B2A`、文件夹紫 `#6F57B5` |
| 应用界面背景/文字 | 系统语义颜色，自动适配深浅色，不把网页色板硬铺到所有原生控件 |
| 字体 | UI 使用系统字体；正文 `.body`、说明 `.caption`、标题 `.headline`；数字计时等用等宽数字 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32pt；相邻控件 8、组间 16–24、窗口内容边距起点 20 |
| 圆角 | 自定义内容容器起点 10pt；嵌套同心处理；系统按钮和窗口圆角由系统管理 |
| 动效 | 局部反馈起点 120–180ms；状态转换 200ms 内；尊重 Reduce Motion |
| 颜色语义 | 错误、警告、成功使用系统语义；品牌色不能覆盖状态意义 |

品牌色集中在产品身份和少数内容点缀，控件默认尊重系统风格和用户强调色选择。Apple 当前 Branding 指南同样强调克制使用品牌色、使用熟悉组件且品牌让位内容。[来源](https://developer.apple.com/design/human-interface-guidelines/branding)。

自定义文字配色发布检查目标：普通文字至少 4.5:1，大字和有意义的图形至少 3:1；这些是本方案验收基线。浅/深色分别测试，禁用态不得拿正常态对比结果替代。不能用低透明度品牌色充当所有说明文字。

## 5. 三种产品壳

| 形态 | 默认结构 | 本方案初始尺寸 | 关闭与恢复 |
|---|---|---|---|
| 菜单栏快速工具 | 状态、一个主操作、最近结果、设置入口 | popover 宽约 320pt，复杂内容另开窗口 | 点击外部收起；退出在菜单里明确提供；设置可重新打开 |
| 单任务窗口 | 输入 → 参数 → 主操作 → 输出 | 600×440pt，最小 480×360pt | 关闭窗口不混同停止后台任务；重新激活恢复合理状态 |
| 有历史的工具 | 可折叠列表＋详情＋工具栏 | 840×560pt，最小 640×420pt | 窗口独立选择；窄窗口收起列表；保留任务与历史 |

以上尺寸需要结合真实内容和本地化调整。每个产品明确 Dock 是否显示、是否常驻、是否允许多窗口。菜单栏工具不要强塞三栏管理界面；简单工具不为家族统一而添加无用侧栏。

采用标准标题栏、交通灯、菜单、设置窗口和文件选择器。自定义只放在功能内容区。窗口缩小时优先换行/折叠再滚动，不裁掉主操作。提供鼠标、键盘和可访问名称，窗口拖拽区域与系统控制保持可靠。

## 6. 命令与状态统一

- 设置 `⌘,`；退出 `⌘Q`；关闭窗口 `⌘W`；搜索在有搜索能力时使用 `⌘F`；遵循系统复制、粘贴、撤销习惯。全局快捷键必须可改、可关闭，并检测冲突。
- 常用操作在适用的菜单与工具栏保持相同名称；菜单的启用状态跟随当前窗口与选中对象。不要把所有菜单项都装饰上图标。
- 每个页面一个明确主操作，例如「开始计时」「转换 3 个文件」。不要用「确定」代替具体动作。
- 输入、执行、输出顺序统一；运行中显示阶段/进度及可行的取消；成功就地展示结果，复制类操作给轻反馈。
- 空状态说明能做什么并给入口；失败显示原因和下一步，保留用户输入；无权限说明用途并提供系统设置入口与重试。
- 有网络依赖时提供离线状态；权限拒绝、试用结束、无内容都不能伪装成空白页。
- 删除优先可撤销；无法恢复的删除明确说明对象和后果。批量操作部分失败时保留逐项结果。

| 状态 | 所有者 | 持久化 | 命令范围 |
|---|---|---|---|
| 主题、快捷键、开机启动选择 | 每个 App 设置 | 持久化 | App 全局 |
| 文件列表、历史记录 | 每个 App 数据模型 | 按隐私与历史设置保存 | 操作明确对象 |
| 选择项、搜索、滚动位置 | 每个窗口 | 按窗口恢复 | 当前焦点窗口 |
| 临时提示、popover 展开 | 当前界面 | 不持久化 | 当前界面 |
| 长任务进度 | 任务模型 | 是否恢复由产品定义 | 任务 ID，不跟随窗口销毁 |

## 7. 量产组件与发行者识别

建立一个共享 Swift Package 的设计建议：`BrandAssets`（母标与标识配置）、`DesignTokens`、`AboutView`、`SettingsSections`、`EmptyState`、`ErrorState`、`PermissionExplanation`、`SupportLinks`。这些是待实现模块清单，本次不是已编译组件库。

每个新产品只填写：名称、功能隐喻、强调色、窗口类型、主操作、权限解释、支持地址、隐私说明、最低系统版本、发行渠道与许可证策略。网站共享导航、截图比例、下载区、隐私/支持入口；App Store 发行者身份与实际注册主体保持一致。不要使用未注册的公司名冒充卖方。

命名可用「{品牌名} + 简短功能名」，也可保留独立产品名并统一「by {品牌名}」。一旦选择，在官网、关于页、安装包、支持邮件和发布说明中保持一致。避免所有名称都缩写成两字母而难以搜索。

共享设置的“样式和分组”不等于跨 App 自动共享隐私数据。同步账户、订阅、诊断上传或剪贴板记录必须由各产品明确设计，不能因同属品牌而默认开启。

## 8. 每款工具发布门槛

1. 把三个以上家族 App 图标并排，在 16/32/64px、灰度和目标系统外观中辨认；靠形状能区分。
2. 在真实目标 macOS 上验证 Dock、Finder、菜单栏、关于页和深浅背景，不以网页预览替代。
3. 用键盘完成核心操作；验证设置、退出、撤销、错误恢复与窗口重新打开；测试权限拒绝和离线（如适用）。
4. 检查 VoiceOver 名称/顺序、焦点、Increase Contrast、Reduce Transparency、Reduce Motion 与长文本布局。
5. 统一版本信息、支持和隐私入口；不出现另一产品残留文案；发布前检查所用 Xcode、最低 macOS、图标资源路径。

当前范围：规范、Logo 概念与静态家族示例。浏览器视觉审查只证明设计稿显示效果；公司名、真实产品清单与部署目标尚未提供，不宣称完成实际 App 集成或平台发布验收。
