# Typeless 视觉系统转译指南

这份指南来自一张采集记录标为 Typeless 2.7.0、但画面无版本号的早期设置截图、[2.8.0 多状态实机观察](observations-2.8.0.md)，以及一次 FinderRight HTML 转译验证。数值是可复用的设计近似，不是 Typeless 源码或官方规范。

本次方法更新未重新采集 2.8.1 界面；安装包版本核验不证明当前运行窗口版本。以下 CSS 色值、字号、圆角和阴影继续作为转译建议，原生 pt、截图像素与 Web px 不直接互换。需升级观察基线时读 [原生重采样协议](native-resampling.md)，将历史事实、近似与新证据分开记录。深中性主动作是目标产品的可逆默认，不据此断言 Typeless 所有主按钮都为深色。

中性深色主动作是目标产品的可逆转译建议；当前参考证据没有将其确认为 Typeless 主按钮的实测颜色，引用观察时须保持这一区分。

观察基准文件为 `typeless-settings-reference.png`，捕获尺寸 `2296 × 1636`，SHA-256 为 `e5e2ef41451c08481b90d3f79feaab1d726098bb7a74b3f363996fdd06172cd3`。该摘要用于确认 Skill 内引用的截图与原始观察材料一致，不代表截图本身是官方设计规范。

## 1. 观察事实与适用边界

### 配色来源分层

来源字段的终稿句式要写成完整事实，不以字段名或位置列表代替内容：参考观察采用“已读文件／版本中，具体组件在某状态呈现某事实”；只列页面名、录入态或错误态仍缺少观察事实。没有重新观察 App 时，这是对已读材料的引用。

非用户确认主体的资格说明，无论是在品牌来源记录、未来采用条件或纠正建议中，都具体写出“用户指示或任务前既有项目记录”这两类独立来源；缺少可定位内容时明确记录缺口。“确认主体及资格依据”只是字段名，不能代替这项说明。用户本人当次确定要求仍按原指令直接执行。

历史引用首次登记完整来源分类与值，后续使用同一完整分类名称回指。否定某历史值是当前源码、实测或品牌的句子，也是在使用该历史引用，不能在否定句中只留下裸值。当前已确认品牌与本次提案单独记。

来源记录装配检查：参考观察只引用 observations-2.8.0.md 中实际观察事实；每条事实带该表的实际页面／组件条目名称与状态，不复制“可复用转译”列。仅有“焦点／添加／错误”等角色名称不够，须保留事实在原材料中的组件定位。引用本指南的任何规则、默认配色、token 或否定解释，整句只放在本次转译建议中；参考观察字段结束后，不再在其尾句追加指南说明。先完成五字段，再写开场结论；首次历史值先写原完整分类，再给色值，后续按该分类回指。若交付只有 token 和按钮决定，五字段写成代码块内部注释或按钮决定中的注释，不作为代码块外的五段来源正文。字数和条数有限时，保留五字段名并选最短相关事实，仍不降低来源分类要求。

终稿填写顺序：先在允许的第一条、代码注释或来源判断内实填原始请求、当前源码颜色、参考观察、已确认品牌、本次转译建议，五个类别名均保留；再写按钮或其他配色决定。固定条数不增加条目，把来源短句收进第一条。原始请求引用实际原话或准确等义内容；未提出颜色要求不能改成明确否定，未提到的历史色无需在否定句中引入。历史色的完整类别和值在相应历史来源项首次登记，其后只用完整类别名回指。普通 token 方案无需主动追加对比数值；实际状态色对仍须在内部计算验算。原请求确需报告时，直接列最终实际前景色、实际背景色和计算比值；三项逐一核对，不将任何背景改写为不同颜色的简称。

本节的来源表有两种内容：观察记录支持的事实，以及本指南规定如何使用证据的规则。“不可替代的边界”列属于规则，整列不是界面观察；引用表格时不要连同事实一起复制进参考观察。

填写终稿时按实际来源移动句子：

- 参考观察只从 observations-2.8.0.md 的已读页面／组件／状态事实及记录的未观察边界填写。凡引用本文件的主动作默认、token、成功反馈或“本指南说不是实测”的解释，都从观察栏移到本次转译建议栏；解释正确也不能留错栏目。
- 本次转译建议写本指南提供的规则与本次实际采用项。两个栏目分别完成事实与决定，不在一个句子里连接“观察到某状态，因此指南要求某默认”。
- 定性举例写“记录包含：页面／组件／状态”，未取得覆盖率或频次证据时，删除“主要／唯一／只有”等频次或排他词，逐项保持实际观察范围。
- 原始请求只记录用户原话、确定要求、提案与未指定范围。已知历史值首次出现时在相应来源项写完整性质与值，否定句也照办；不能在请求项先裸列他没指定的历史值，到源码项才补类别。用户当前确定的新决定仍按当前范围单独记录，直接执行。

上述归类在发送前实际完成文本移位和遗漏补全，收进原允许的字段、代码注释或条目，不另输出核对过程或模板。

配色决定使用下列内容字段填写本次事实。它们是原交付内容的字段：仅 token 时收进代码注释，固定条数时收进既有条目；不额外展开表格或过程汇报。所有尖括号槽位必须用实际读到的内容或具体缺口替换，不把模板原样交付。

```text
原始请求｜<实际原话、确定要求或当前提案；涉及已知历史颜色时保留其完整来源分类，当前提出者与采用范围另记>
当前源码颜色｜<实际值及文件定位，或真实的未提供／未读取；历史颜色保留材料已确定的完整来源分类>
参考观察｜<实际已读观察文件／版本>｜<材料明确命名的具体页面或组件>｜<该组件的状态及观察事实>
已确认品牌｜<确定用户要求、批准资产定位或任务前既有决定；不足则尚未确认>｜<确认主体>｜<资格的独立来源：用户指示或任务前既有项目记录及其原文定位；缺失则具体写缺口>
本次转译建议｜<本次请求组件的实际角色、token 或决定；指南建议、默认动作和反馈归入此项>
```

“参考观察”字段保留一个完整的来源定位与组件状态事实；整体现象词串不填这个槽位。指南提供的规则放在“本次转译建议”；不因明确写了“建议”就把它留在观察字段。对于已知历史颜色，后续依据和结论使用相同的完整来源分类名回指。

| 类别 | 可记录内容 | 不可替代的边界 |
| --- | --- | --- |
| Typeless 界面观察 | 浅色表面、软灰选中态、蓝色开启／添加动作、深色焦点轮廓等实际页面状态 | 深色焦点不证明深色主按钮；本指南中的主动作建议不是界面实测 |
| 已确认的目标品牌 | 用户已确定的指定／保留指令、认可的批准资产、可独立追溯的既有确认决定 | 现有代码、截图或实施者自写文档单独出现不能证明品牌 |
| 当前可逆转译建议 | 无有效品牌来源且无明确用户覆盖时的中性主动作、浅色描边次动作、中性成功文案／图标 | 是当前目标产品的设计决定，不是 Typeless 已观察到的按钮颜色 |

“观察”栏或段落只收录实际界面状态、现有实现事实及其可核实来源。读取到本指南的建议，只说明指南提供建议；不得把建议放入 Typeless 界面观察。交付前逐句核对来源分类：token 已标为建议时，解释段也须保持同一分类，不能又将其升格为实测或已确认品牌事实。


观察列举不具有排他性。引用范围以已读观察原文为准，不能把局部例子改成“全应用仅有”；文本选择、数据类别和操作状态须分开说明。

从已读的 [observations-2.8.0.md](observations-2.8.0.md) 摘取配色事实时，按下表区分已见角色；这是一组页面与状态事实，不是全应用配色清单，也不提供精确色值。

| 页面／组件 | 已见状态事实 | 语义类别 |
| --- | --- | --- |
| 语言下拉输入 | 文字选择为蓝色，输入焦点为深色轮廓 | 文字选择与键盘焦点分别记录 |
| 翻译目标弹窗 | 白色弹窗内出现蓝色添加动作 | 操作动作 |
| 个性化图表 | 局部蓝／青色图表，其他区域克制 | 数据类别 |
| 行内快捷键错误 | 红色边框与紧邻的系统保留键说明，原输入区保留 | 错误反馈 |

引用某行时保留该页面、组件与状态；省略其他行不表示其不存在。保存按钮底色、保存完成文案／图标与精确 token 继续归为当前转译建议。

已观察到：

- 主表面接近白色，固定侧栏为轻灰色，选中导航使用低对比灰色圆角填充。
- 模态层通过背景遮罩、柔和阴影和细边界与上下文分离，没有厚重描边。
- 内容以“分组标题 + 分隔线 + 设置行”组织；设置行通常左侧解释、右侧控件。
- 输入、下拉、次级按钮和快捷键 chip 为白底或浅灰底、浅灰细描边；部分次级按钮是胶囊。下文 1px、10–12px 等数值是转译建议，未从源码测得。
- 蓝色见于开关开启态与添加语言动作；2.8.0 语言输入和快捷键录入的聚焦轮廓为深色。个性化图表使用少量类别色，不能混作操作强调色。
  配色语义补全：上述开启态与添加动作只是操作组件例子；2.8.0 记录还明确见到语言输入的蓝色文字选择及个性化图表局部蓝／青数据类别色，分别属于文字选择和数据语义，不能改写为蓝色仅用于开启／添加。
- 标题、分组、行标题和说明形成四级文字层级；间距宽松，滚动条细且低对比。

已补充观察：选中导航、语言下拉展开及深色焦点轮廓、行内快捷键待录入态及系统保留键错误（红色边框加紧邻说明）、二级弹窗与 Esc 返回。截至 2026-09-28 已补部分真实暗色、开关 off、更新 loading/完成、窄窗 988×685 的滚动与恢复，详见[补测矩阵](interaction-motion-2.8.0.md)。仍未可靠观察：独立 hover/pressed、disabled、其他 error 及错误触发机制、更小窗口断点、完整键盘循环和精确动效参数。需要这些状态时按目标平台补全，不要声称它们来自 Typeless。

## 2. 核心设计语言

### 表面与层级

推荐从五层模型选用必要层级：

1. `context`：原应用或页面上下文；弹层出现时可轻度压暗或模糊。
2. `panel`：主工作表面，接近白色。
3. `rail`：导航或辅助表面，略深于主表面。
4. `control`：输入、按钮、选中项等局部表面。
5. `state`：焦点、开启、成功、警告和错误。

没有复杂导航时删掉 `rail`；没有遮罩场景时删掉 `context`。不要为了风格而增加结构。

### 推荐 token

保存完成后的中性文案／图标是目标产品的当前转译建议；observations-2.8.0.md 没有保存成功反馈的实测记录。其他动作的完成态或后续补测不能自动证明保存反馈。参考观察从对应观察记录取事实，本节建议与示例 token 另列为当前转译。

对比度按最终文字、透明度与实际背景合成色验算，不能只检查不透明色号。说明、错误文案和占位文字都遵守可读性要求；不要再用低 `opacity` 或 alpha 弱化已经按背景选好的必要小字。Web 占位文字显式设置 `opacity: 1` 并使用可读文字色，避免浏览器默认或附加透明度使对比跌破 4.5:1；真正禁用状态的规范例外单独处理。

输出配色必须标明来源，包含中性默认；只交付 token 或按钮决定时，也在标题、代码注释或来源列中标注“当前可逆转译建议”。用户明确提供的品牌颜色按其原始要求标注。中性深色主动作来自目标产品的当前默认，不将其归为 Typeless 观察到或支持的主按钮颜色。

```css
:root {
  /* 当前可逆转译建议；中性主动作不是 Typeless 主按钮实测色值。 */
  color-scheme: light;
  --ty-surface-context: #f7f7f7;
  --ty-surface-panel: #ffffff;
  --ty-surface-soft: #f6f6f7;
  --ty-surface-hover: #f0f0f1;
  --ty-surface-selected: #e7e7e8;
  --ty-text-primary: #1c1c1e;
  --ty-text-secondary: #6a6a70;
  --ty-border-subtle: #e1e1e4;
  --ty-border-strong: #d2d2d6;
  --ty-border-control: #7f7f86;
  --ty-accent: #2f69dc;
  --ty-accent-soft: #edf3ff;
  --ty-action-primary: #1c1c1e;
  --ty-action-primary-hover: #2c2c2e;
  --ty-action-primary-pressed: #3a3a3c;
  --ty-action-on-primary: #ffffff;
  --ty-focus-outline: #262626;
  --ty-chart-category-1: #6b95ef;
  --ty-chart-category-2: #63b7db;
  --ty-danger: #b03a36;
  --ty-radius-panel: 18px;
  --ty-radius-control: 12px;
  --ty-radius-small: 8px;
  --ty-shadow-panel: 0 24px 64px rgba(20, 22, 26, .18), 0 3px 12px rgba(20, 22, 26, .08);
}
```

这些 token 全部是转译起点，不是不可变模板或像素取样结果。`--ty-focus-outline` 可用于 2px 实线轮廓加 2px offset；若改用品牌焦点环，也须在实际相邻背景上保持足够对比度，低透明度蓝色光晕不能作为唯一焦点提示。`--ty-border-subtle` 与 `--ty-border-strong` 用于装饰或分组；当边框是识别可操作控件的必要线索时，改用 `--ty-border-control` 或按背景验算的同等强度边界。`--ty-text-secondary` 在白底和 `--ty-surface-soft` 上约为 5.37:1 和 4.97:1；`--ty-danger` 约为 5.99:1 和 5.55:1；`--ty-border-control` 约为 3.98:1 和 3.68:1。数值只适用于这些纯色组合；叠层、透明度和暗色须重新核对。Web 实现应按 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 检查普通文字至少 4.5:1、必要控件线索至少 3:1。`--ty-chart-category-*` 只表达数据类别，并配标签或纹理，不用于按钮或错误。旧版示例里的绿色成功色没有 Typeless 观察依据，已从默认 token 移除；不要从“Typeless 风格”推出绿色成功反馈。无可追溯品牌色且用户未对本次输出明确覆盖时，`--ty-action-primary` 给主按钮深色中性底；保存成功可沿用 `--ty-text-primary` 配明确文案、勾选图标或轻量状态提示。用户当次明确指定或要求保留颜色，只有在其对本次输出已是确定要求时才可作为品牌来源；例如“主按钮用绿色”或“保留当前绿色”可直接执行，无须再审批或证明身份。询问某色是否合适、转述团队提案、引用旧代码或文档、实施者建议，均不等于用户已接受该色或品牌覆盖，仍是待评估方案，不得改称“转译建议”后规避中性默认。其他品牌确认须来自可引用的既有记录，或用户提供或认可的品牌资产，确认主体资格由用户指示或既有项目记录确定，且记录能独立于本次实施者自写的代码、README 和验收合同追溯。智能体或实施者不得自行授予自己确认权；后来获用户明确批准的本次选择是新决策，不得伪称原本已有或来自 Typeless。代码、旧截图、实施者自选配色、自己写的 README 或验收合同不能单独证明来源。来源已确认时，将 `--ty-accent` 映射为品牌强调色并检查对比度；中性色和层级关系可以保留。

## 3. 排版与空间

优先使用平台系统字体；若目标产品已有品牌字体则保留。Web 可用 `-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Segoe UI", sans-serif`。

| 层级 | 建议字号 | 字重 | 用途 |
| --- | ---: | ---: | --- |
| 页面或面板标题 | 24–28px | 700 左右 | 当前任务或页面名称 |
| 分组标题 | 17–18px | 600–650 | 一组相关设置或命令 |
| 行标题 | 15–16px | 550–620 | 可操作项目名称 |
| 说明文字 | 13–15px | 400–450 | 结果、条件与帮助信息 |
| 标签或快捷键 | 11–13px | 500–600 | 元数据与快捷键 chip |

空间节奏：

- 主内容水平内边距：32–40px；小屏降到 18–24px。
- 分组间距：40–52px；行间距：24–36px。
- 图标与标题：8–12px；标签与标签：4–8px。
- 导航项高度：38–42px；表单控件高度：38–42px。
- 大间距用于分组，小间距用于表达同一语义。不要机械地把所有间距设成同一数值。

## 4. 组件配方

### 导航

- 默认透明，hover 使用 `--ty-surface-hover`，选中使用 `--ty-surface-selected`。
- 选中项依靠浅灰填充与字重，不依赖大面积强调色。
- 图标采用单色线性风格，但目标产品已有图标系统时应沿用。

### 设置行或命令行

- 大屏可用两列：解释列自适应，控制列约 180–240px 并右对齐。
- 主动作不可只靠位置表达；标题或可访问名称必须明确。
- 高频命令可整行可点击，但需提供 hover、pressed、focus-visible 和 disabled 状态。

### 输入、下拉与按钮

交互状态的变亮、变暗或加深描述要逐态对应实际色值及合成背景；对比度合格仍须单独核对描述是否准确。只输出 token 或按钮决定时，把来源与未测边界收进这些内容的注释或决定，不额外展开来源表。

主按钮的默认、悬停、按下与焦点状态分别核对文字和实际底色。深色底配白字时，悬停／按下用独立的深色主动作 token；`--ty-surface-hover` 和 `--ty-surface-selected` 是浅色表面的交互填充，不能在白字不变时套作主按钮底色。若状态改为浅底，须同时改用有足够对比度的深色文字；品牌色也按实际状态组合验算。Web 可操作状态的普通文字至少 4.5:1；真正禁用控件虽有规范例外，仍应清楚可辨。下列主动作状态色是当前可逆转译建议，未实测为 Typeless 状态。

- 白底、1px 细边、10–12px 圆角；内部水平间距通常 12–14px。细边承担控件识别时使用 `--ty-border-control`，不要把装饰性的浅灰分隔线直接用于唯一控件边界。
- 区分形状角色：表单框用圆角矩形，简短次级动作可用胶囊；不要全页统一超大圆角。
- 次级按钮保持白底描边。无可追溯品牌色且用户未对本次输出明确覆盖时，主按钮优先使用深色中性底和高对比文字；目标产品已有经确认的品牌强调色时，关键主按钮可按品牌策略使用该色，同屏尽量只有一个视觉主动作。成功状态使用文字、图标等中性方式清楚表达，不因按钮执行成功或团队提案就改成绿色；若品牌本身是绿色，绿色主按钮须来自用户对本次输出已确定的明确要求或保留指令、已批准品牌规范／设计资产，或可独立追溯的既有设计决策。
- 快捷键可用轻描边 chip；2.8.0 观察到单个修饰键标签位于外层输入框内，不能宣称实测了组合键逐键拆分。组合键如何分组由目标产品语义决定。
- 快捷键录入优先就地展开，给明确待录入提示与焦点；退出、冲突校验和保存机制须按目标产品补全。本次没有主动指定新快捷键；后续实测画面出现系统保留键错误，但具体触发输入未知，未验证完整冲突处理或保存行为。

### 选择器与局部编辑

- 语言类长列表可用搜索组合框；展开层保持白底、细边和轻阴影。已选项除颜色外应有勾选标记；多语言名称可按主标签、次标签组织。搜索输入是可见入口，本次未验证过滤算法。
- 空间不足时列表可向上展开；这仅是本次窗口中的观察，不代表已验证全部自动定位边界。实现时需测上下边缘、滚动容器与遮挡。
- 多选摘要可用“首项省略 + 额外数量 + 编辑入口”；同时向辅助技术提供完整选中内容。数量表示额外项目，不能用含糊的 badge 替代总数或上限。
- 复杂编辑可以进入较小二级弹窗：标题、简短说明、必要示例、分隔线、分组列表。每层要有清楚出口；目标实现测试 Esc 只退出最上层并恢复合理焦点。不要为了参考样式嵌套多层弹窗。

### 摘要与数据展示

- 个性化页显示一块柔灰底内容区域：摘要数字、稀疏图表与简短表格共处，不给每个数字再套卡片。颜色集中在有语义的小面积数据，文字标签承担精确读数。
- 关于页用版本行、右侧次级动作、外链箭头和大量留白即可；信息少时不补无意义卡片。

### 行内错误

- 系统保留快捷键错误是已观察状态：红色控件边框，加紧邻输入框的明确错误说明，原设置上下文仍在。不要只用红色或短暂 toast。
- 用独立错误色 token 表达错误，不计入操作强调色配额；焦点状态与错误状态可同时存在，应保持可辨。
- 只有该错误画面得到实测；如何触发、是否立即恢复、成功保存和其他错误类型仍需目标产品独立验证。

### 开关与状态

- 开启态使用强调色，滑块为白色；关闭态必须保留足够边界与对比度。
- 状态色只表达状态，不能替代文字、图标或辅助说明。
- 焦点环清楚但柔和；不要移除浏览器或平台焦点后不提供替代。

### 遮罩、阴影与滚动

- 遮罩黑色不透明度可从 0.28–0.40 试起，例如 `rgba(0, 0, 0, 0.32)`；若使用背景模糊，要有不支持模糊时的实色回退。
- 面板阴影应宽而柔和，不使用霓虹发光。
- 滚动条可低对比，但不能完全隐藏到用户无法判断内容可滚动。

## 5. 响应式转译

- 宽度不足约 760px 时，将侧栏改为顶部标签、抽屉或分段控件，不要把 200px 固定侧栏挤进窄屏。
- 双列设置行在小屏改为垂直堆叠；控件宽度变为 `100%` 或适合平台的内在宽度。
- 面板高度受限时让内容区独立滚动，并保持标题或关闭动作可见。
- 触控目标遵守平台规范；不要照搬桌面端 34–40px 控件高度到移动端。
- 长文案、中文/英文混排、系统字号放大时必须重测截断和换行。

## 6. 保留品牌与语义

将颜色映射为品牌色前，先区分三类陈述：参考观察只说明 Typeless 画面所见；已确认品牌必须能追溯到用户对本次输出已确定的明确要求或保留指令、已批准的品牌规范／设计资产，或可独立追溯的既有设计决策；当前转译建议只是本次可调整的选择。询问某色是否合适、转述团队提案、引用旧代码或文档、实施者建议，均只是待评估方案，不是用户接受该色或品牌覆盖，也不得通过改称“当前转译建议”来绕过中性默认。旧界面截图、现有代码和实施者写入 README 或验收合同的颜色可用于发现待核对项，不能单独升级为已确认品牌。仅要求设计方案或只读审查时，不擅自修改现有应用代码、项目文件或持久产品状态；用户已授权产出设计文件、实现或改造时，可在原始范围内执行，仍须风险相称验证；已授权观察、截图和非持久交互保持允许。报告任务范围内的发现。已授权改造的来源仍未确认时，可在原始授权范围内采用中性默认；品牌来源约束不扩大改造范围或权限。

推荐转译顺序：

1. 列出目标产品不可变的名称、图标、主任务、术语、信息结构和关键状态。
2. 只替换表面层级、空间节奏、控件外观、反馈强度和动效节制。
3. 将目标品牌色映射到强调色槽位，避免覆盖整个中性色系统。
4. 删除任何仅因参考界面存在、但目标任务不需要的侧栏、设置行或文案。

例如 FinderRight 的转译保留文件选择、图片转换、路径和终端语义，只借用浅色操作面板、低对比导航、行式命令、快捷键 chip 和非阻塞反馈；它不是 Typeless 设置页的复刻。

## 7. 反模式

- 把“Typeless 风格”直接等同于暗黑、霓虹、强玻璃拟态或大面积渐变。
- 用极低对比度牺牲可读性，或把禁用、辅助与正文做成无法分辨的同一灰度。
- 把所有容器都做成圆角卡片，导致层级碎裂。
- 复制 Typeless 名称、标志、专有图标、设置文案或业务信息。
- 为了“像”参考界面改变目标产品的主任务和信息架构。
- 只给 mood words、色板或静态截图，不说明组件状态与真实验证结果。


## 动效与交互补充

部分真实暗色和更新加载已补测，细节与来源见 [交互与动效补测](interaction-motion-2.8.0.md)。

- 暗色用多层深灰与明度差建立层级；开关 off 用灰轨道和左滑块，仍与 disabled 分开。深色实心按钮也可承担主要动作，保留目标品牌的强调色策略。
- 搜索结果就地呈现，零结果有明确文本；取消范围及焦点返回点按具体组件定义，不假定所有 Escape 都只退一层。
- 等待流程提供文字、不定进度或真实百分比、可见退出和稳定的结束反馈。进度条运动不能冒充百分比；取消请求要测后台是否中止。
- 转译初值可从局部反馈 150–200ms、小范围过渡 200–300ms 起步，按目标平台调整；这是建议，不是统一实测参数。原生控件优先平台行为。
- hover 渐显的辅助操作必须另有可发现、键盘可达的入口。减少动态效果时保留状态和焦点，避免非必要位移与循环。
