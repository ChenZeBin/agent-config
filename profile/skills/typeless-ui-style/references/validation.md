# 实现与视觉验收

产出可运行 HTML、原生界面、交互原型或可交付视觉稿时使用本清单。纯概念讨论可以按风险缩减，但不得把未验证事项写成已验证。

## 1. 先定义验收对象

- 目标环境：浏览器与版本、macOS/iOS/Windows/Android 版本、窗口或设备尺寸。
- 核心任务：用户从哪里进入、要完成什么、成功反馈是什么、如何退出或恢复。
- 关键状态：默认、hover、pressed、focus-visible、selected、disabled、loading、success、error、空状态。
- 视觉边界：目标产品必须保留的品牌、信息架构、术语与平台行为。
- 品牌追溯：分别列出参考观察、已确认品牌和当前转译建议。用户当次明确指定或要求保留颜色，只有在其对本次输出已是确定要求时才可成立，无须证明职务或再次审批；例如“主按钮用绿色”或“保留当前绿色”可直接执行。询问某色是否合适、转述团队提案、引用旧代码或文档、实施者建议，均不等于用户已接受该色或品牌覆盖，仍须作为待评估方案按原始任务判断，不得改称“当前转译建议”后规避中性默认。其他已确认品牌应链接或指向用户提供或认可的品牌资产，或可引用、可独立追溯的既有设计决策，其确认主体资格由用户指示或既有项目记录确定。现有代码、旧截图、实施者自选配色、README 和本次验收合同不能单独充当来源；智能体或实施者不得自行认定自己是负责人或授予自己确认权。本次选择后来获用户明确批准时，记录为新决策，不得回填为既有品牌或 Typeless 来源。

## 2. 静态检查

- token 集中定义，无成片重复的魔法色值和半径。
- 将原始请求与实际源码中的颜色逐项核对：未确认品牌色且用户未对本次输出明确覆盖时，主动作采用中性深色默认，成功反馈采用中性文字、图标等表达；已确认的绿色或其他品牌色按其原始来源保留。不得把团队想用的颜色、本次自选颜色或当前转译建议写进验收标准后反向当作品牌证据。
- 主文本、辅助文本、边框、强调色与状态色层级可辨；必要时测量对比度。
- 页面标题、分组标题、行标题和说明不混成同一层级。
- 没有复制 Typeless 名称、标志、专有图标、设置文案或业务内容。
- 在系统字号放大、长中文/英文文案和 200% 缩放下没有关键内容被裁切。

## 3. 交互检查

- 只用键盘可到达并操作核心路径，Tab 顺序合理，焦点始终可见。
- `Esc`、关闭、返回、取消或撤销行为符合目标平台；没有无出口的弹层。
- hover、pressed、selected 和 disabled 不只依赖颜色；错误与成功状态有文字或可访问名称。
- 滚动区域真的可滚动，滚动条和固定元素不会遮挡内容。
- 触控环境满足最小点击区域，桌面快捷键不会成为唯一操作方式。

## 4. 响应式与目标环境

至少验证：

- 一个主要交付尺寸。
- 一个更窄或更短的边界尺寸。
- 一个长文案或系统字号放大的压力场景。
- 如果交付涉及暗色模式，则单独设计并验证暗色 token；不要自动反相浅色方案。

Web/HTML 必须在真实浏览器中打开并实际操作；原生实现必须在真实 App 或受支持模拟器中运行。源码检查、构建成功或 DOM 存在不等于界面可用。

## 5. 截图与视觉复核

- 截取主要交付尺寸的完整界面，以及至少一个关键交互或状态画面。
- 截图应来自真实渲染目标，不使用仅在编辑器或锁屏层可见的错误画面。
- 与 `typeless-settings-reference.png` 及 `observations-2.8.0.md` 的对应页面、状态对照层级、节奏、控件克制度和强调色使用，不做逐像素复制。
- 复核：是否仍能一眼看出目标产品是什么、当前任务是什么、下一步能做什么。
- 记录未覆盖状态和已知限制。

## 6. 交付陈述

清楚区分：

- 已执行且通过的检查。
- 有截图或运行记录支持的视觉事实。
- 基于观察得出的设计推断。
- 可追溯的已确认品牌，以及仅作为当前转译建议的颜色；新获用户批准的颜色须标为新决策。
- 来源不足的具体缺口与能改变判断的有效证据；用户直接确定的配色或保留可直接执行，不另要求负责人、身份证明或再次审批。中性默认应报告为本次可逆建议，不得写成 Typeless 实测或已批准品牌。
- 尚未验证、需要用户主观确认或真实业务数据才能判断的部分。

自动化可以证明结构、状态与交互是否按预期运行，但不能证明用户一定喜欢这套审美。将截图和可运行产物交给用户判断偏好，不要把“检查通过”写成“审美已获认可”。

仅要求设计方案或只读审查时，不擅自修改现有应用代码、项目文件或持久产品状态；用户已授权产出设计文件、实现或改造时，可在原始范围内执行，仍须风险相称验证；已授权观察、截图和非持久交互保持允许。审查报告任务范围内的发现，不把审查扩展为 UI 重设计。已授权的实现或改造可以采用可逆中性默认，但须限于原始任务范围；品牌来源约束本身不扩大改造范围或权限。

## 7. 选择器、录入与嵌套层专项

- 搜索组合框测试过滤、零结果、长标签、选中标记、上下边缘定位及键盘选择；本次参考观察未验证的行为仍是目标产品必须补测项。
- 多选摘要同时验证可见省略、额外数量与完整可访问名称；到达数量上限要有解释。
- 快捷键录入验证进入、取消、重复或冲突、保存和离开页面；不要为了观察参考应用而更改用户已有快捷键。
- 二级弹窗验证 Esc 只退一层、返回后原选项保留、关闭入口和焦点恢复；完整焦点循环必须单独测试。
- 深色示意图、黑色菜单图片或视频不能作为暗色模式实测证据；数据类别色不能算作大面积操作强调色违规。
