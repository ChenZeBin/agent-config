# 实现与视觉验收

产出可运行 HTML、原生界面、交互原型或可交付视觉稿时使用本清单。纯概念讨论可以按风险缩减，但不得把未验证事项写成已验证。

## 1. 先定义验收对象

- 目标环境：浏览器与版本、macOS/iOS/Windows/Android 版本、窗口或设备尺寸。
- 核心任务：用户从哪里进入、要完成什么、成功反馈是什么、如何退出或恢复。
- 关键状态：默认、hover、pressed、focus-visible、selected、disabled、loading、success、error、空状态。
- 视觉边界：目标产品必须保留的品牌、信息架构、术语与平台行为。

## 2. 静态检查

- token 集中定义，无成片重复的魔法色值和半径。
- 主文本、辅助文本、边框、强调色与状态色层级可辨；必要时测量对比度。
- 页面标题、分组标题、行标题和说明不混成同一层级。
- 没有复制 Typeless 名称、标志、专有图标、设置文案或业务内容。
- 在系统字号放大、长中文/英文文案和 200% 缩放下没有关键内容被裁切。

## 3. 交互检查

- 只用键盘可到达并操作核心路径，Tab 顺序合理，焦点始终可见。
- `Esc`、关闭、返回、取消或撤销行为符合目标平台；没有无出口的弹层。
- hover、pressed、selected 和 disabled 不只依赖颜色；错误与成功状态有文字或可访问名称。
- 滚动区域真的可滚动，滚动条和固定元素不会遮挡内容。
- 触控环境满足最小点击区域，桌面快捷键不会成为唯一操作方式。

## 4. 响应式与目标环境

至少验证：

- 一个主要交付尺寸。
- 一个更窄或更短的边界尺寸。
- 一个长文案或系统字号放大的压力场景。
- 如果交付涉及暗色模式，则单独设计并验证暗色 token；不要自动反相浅色方案。

Web/HTML 必须在真实浏览器中打开并实际操作；原生实现必须在真实 App 或受支持模拟器中运行。源码检查、构建成功或 DOM 存在不等于界面可用。

## 5. 截图与视觉复核

- 截取主要交付尺寸的完整界面，以及至少一个关键交互或状态画面。
- 截图应来自真实渲染目标，不使用仅在编辑器或锁屏层可见的错误画面。
- 与 `typeless-settings-reference.png` 对照的是层级、节奏、控件克制度和强调色使用，不是逐像素复制。
- 复核：是否仍能一眼看出目标产品是什么、当前任务是什么、下一步能做什么。
- 记录未覆盖状态和已知限制。

## 6. 交付陈述

清楚区分：

- 已执行且通过的检查。
- 有截图或运行记录支持的视觉事实。
- 基于观察得出的设计推断。
- 尚未验证、需要用户主观确认或真实业务数据才能判断的部分。

自动化可以证明结构、状态与交互是否按预期运行，但不能证明用户一定喜欢这套审美。将截图和可运行产物交给用户判断偏好，不要把“检查通过”写成“审美已获认可”。
