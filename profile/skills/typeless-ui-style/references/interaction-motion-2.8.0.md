# Typeless 2.8.0：交互与动效补测

观察日期：2026-09-28；补充实测：2026-09-29。环境：macOS 15.5（24F74），已安装的 Typeless 2.8.0，原生窗口截图 2160×1500。截图像素不是逻辑点或 CSS px。以下是特定路径的观测，不是全应用验收或官方设计规范。

## 证据分层

- **运行态**：真实操作后的画面和可访问性树（AX），原始操作日志及截图摘要保留在本地。截图可能含私人使用数据，不随 Skill 发布。
- **静态声明**：只读检查安装包 `app.asar` 的渲染资源；没有执行提取出的代码。组件局部声明与依赖库默认值分开，不声称为最终 computed style。
- **转译建议**：目标产品的设计选择，需要在目标环境重新验证。
- **未验证**：触发失败、观测通道不完整或缺少连续帧时，保留未知，不以源码补成实测。

本次 AX 与画面有异步更新：刚操作后的 AX 可能仍是旧状态，下一张图已变化。必须按稳定的最终画面与新 AX 确认；一次空树不代表没有弹窗。连续截图也受工具等待、捕获延迟和指针高亮影响，不能用请求耗时推算动画时长、FPS 或 easing。

**禁用的语义边界**：三项上限是实测的“变灰且当前不可添加”状态，但 AX 暴露为静态文本，没有原生 disabled button 标记。Tab 跳过并不证明说明可由键盘用户获取。目标产品应给可感知的限制理由，不照搬仅靠悬停提示的路径。开关 off、空白词汇提交与该上限状态继续分别处理。

**焦点与激活不能混同**：三项状态的 Tab 循环已采样，但删除按钮没有可访问名称。两项状态中 Return、Space 未观察到删除，鼠标点击之后删除成功；由于输入与 AX/画面异步，不能据此宣称产品永久不支持键盘删除，也不能判完整键盘通过。复测需要逐项核对焦点可见、激活结果和返回位置。

对外报告这项边界时，明确写“Tab 聚焦已观察，键盘激活未验证”。说明 Return／Space 的删除结果未确认仍有价值，但不能省去激活状态的结论。

**辅助操作的显隐**：语言行在指针进入后出现左侧点状拖动手柄与右侧删除图标，背景变软灰。实际已看到显隐前后态；200ms 仍只来自下文静态声明，没有连续时间轴支持实测时长。

### 尚未完成的边界

- **窄窗扩展范围**：已测 1080×750 → 988×685 及滚动恢复；尚未验证更小尺寸、断点与所有页面，988×685 不是最小尺寸结论。
- **排序**：对实际可见手柄执行拖动，稳定后仍是中文、英语；未取得成功换序、持久化与恢复证据。工具输入命中与异步更新存在限制，不能把拖动尝试或手柄存在当作排序通过，也不据此直接判产品缺陷。
- **键盘**：特定三项面板的 Tab 正反向序列已测；全流程纯键盘添加、删除激活、排序、焦点可见性仍未完成。
- **精确动效**：截图没有可靠捕获连续中间帧。录屏工具启动尝试未形成可用录制；没有时长、曲线、FPS、快速中断/反向和 reduced motion 的运行测量。工具调用耗时或等待时间不能当作动画时长或 FPS，也不能填补连续帧缺口。

## 细节与转译

### 1. 颜色和表面按状态分配

真实暗色由多层深灰建立层级，不是将整张浅色截图反相。开启的蓝色、关闭的灰色、导航的软灰选中态各有语义。更新完成的主按钮采用深色实心，并非所有主要动作都用蓝色。迁移时仍保留目标品牌强调色；浅色仍是默认起点，明确需要暗色时才扩展 token 与状态检查。

### 2. 退出规则要写到具体层

同一个 Escape 在翻译目标里退一层，在快捷键录入里关闭设置。在目标产品里优先选符合平台与任务预期的取消规则，不照搬这个差异。每个弹层/录入流程单独写出：打开来源、初始焦点、编辑是否立即生效、Escape 范围、关闭后的焦点、值如何恢复。要保留可见取消方式，不能把快捷键当唯一出口。

归纳实测时保留这个反例：不能写“Typeless 的 Escape 总由最内层消费”，再把关闭整层设置列为例子。目标平台未指定时，“最内层先取消”只能作为候选设计；核对该平台的取消、提交与焦点惯例后再确定，不能把建议冒称参考应用的统一行为。

### 3. 加载是一个可结束的流程

参考路径是“检查中 → 明确结果 → 确认返回”。加载状态有文字、运动指示与退出入口；结果态留在弹窗中，不是转瞬即逝的 toast。目标产品无真实百分比时使用不定进度，不能把蓝段占比伪装成完成率。取消按钮的视觉存在不等于后台任务真的中止，必须另测。确认恢复后可再次进入原任务。

为目标产品编写取消验收步骤时，明确要求验证后台任务确实中止；只观察到弹窗关闭或界面不再更新不足以证明请求、写入和副作用停止。按任务语义核对是否还有迟到结果，并记录取消范围及部分结果如何处理。

汇报本次补测范围时，明确把“正在检查更新…”和不定进度条列为已观察的**更新加载态**，把版本结果列为完成态；只看到取消入口时，将“取消是否中止后台请求”列为未证实。不要用笼统的“更新已测”替代这三个状态边界。

### 4. 少量视觉变化承担明确作用

开关滑块位置和颜色共同表意；搜索结果在控件旁就地呈现；录入错误应靠边框与文字共同说明；弹窗用遮罩隔开上下文。动效主要用于状态衔接、逐步揭示辅助操作和持续等待反馈，不应为了“高级感”加入弹跳、长位移或全页缩放。

## 再测方法

1. 记录版本、窗口实际尺寸、原偏好及样本数据；只对可恢复的路径操作。
2. 为每项记录触发动作、操作前/中/后画面、稳定后的 AX、退出与恢复结果。异步画面与 AX 分别标时间，不合成并不存在的同一瞬间。
3. 精确动效需有可靠时间轴的录屏或受支持的帧/性能采集，覆盖进入、离开、中断、反向触发和 reduced motion。工具调用时间不是呈现时间。
4. 代码中找到参数时写清“局部声明 / 依赖默认 / 最终 computed style / 运行测量”哪一层，保留版本和可核对位置。
5. 对未触发的状态记录已尝试动作、通道限制和下一步条件。不要为覆盖率编造结果，也不要把参考应用的潜在阻力机械转译到目标产品。
