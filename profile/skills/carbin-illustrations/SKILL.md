# 小黑配图

将正文中的关键判断变成读者一眼能读懂的极简漫画场景。默认视觉规则见 [风格与提示词](references/visual-style.md)。小黑是本 Skill 的配图称呼；没有角色参考时仍使用原创通用人物，不宣称已有固定 IP。用户明确的角色、配色、比例、文字和数量要求覆盖默认规则。

## 理解与规划

读取用户提供的正文或文件；链接通过适用的读取工具获取，不能只凭标题猜正文。缺少内容且没有可用上下文时，问一个必要问题；用户要求先做示例时可选简短示例，但明确它是测试内容。

提炼核心观点、认知转折和适合图解的段落。不要平均分配图片。每张图只解释一个意思；短文通常一张，长文按真正有用的重点规划，不凑固定数量。

生成前用简短清单写出插入位置、核心意思、场景隐喻、角色动作与情绪、必要元素、构图对比、比例和图中文字。选出能体现时间、代价或结果的一两处叙事细节，并说明它们怎样支撑同一个观点；没有帮助时省略。纯观点不必硬画成流程图。用户要求“仅规划”或“不生成”时，到此结束，不调用生图。

默认追求“极简但有戏”：让表情和身体动作承担情绪，让大小、远近和疏密引导视线，允许单一强调色形成有分量的色块。增加表现力不等于填满背景，不套用每图必有汗滴、旧鞋或速度线的模板。用户明确要求更克制、更素或图标式时遵从。

## 生成

用户要求生成时，完成简短规划后直接使用内置 `image_gen`，每张分别调用。需要看本地参考图时先用 `view_image` 检查，再通过工具支持的引用方式传入。参考图用于保持身份或风格，不默认照搬其布局。

没有用户角色参考时，采用风格文件里的原创通用线稿人物，不称其为用户固定 IP。角色必须推动、修订、比较或操作图中的关键物件，不能缩在角落作头像装饰。

内置生图工具不可用或报错时，明确图片未生成，可以保留规划和提示词；不编造图片、链接或保存路径，不把 SVG/HTML 占位图冒充生图结果，不自动改走付费 API 或要求用户交出密钥。用户明确选择其他生成方式后再按其授权执行。

## 检查与反馈

打开实际生成图，依据 [检查清单](references/qa.md) 核验语义、人物动作、色彩、留白和文字。明显不合格时做针对性修订，再看结果；重复出现同类问题先改清楚对应提示词，不盲目重试。持续失败时报告未解决项。

区分“改这张图”和“以后都这样”：前者只改当前图；用户要求长期固化反馈时，更新本 Skill 对应的风格或检查规则，并用同一测试内容重新生成验证。对新建或修改的 Skill 按当前环境要求执行评测，不以一张图的美观代替行为测试。

## 保存和交付

用户指定位置时复制到该位置；项目配图默认保存到项目内 `assets/<article-slug>-illustrations/`，如 `01-feedback-loop.png`。预览图可保留工具的默认生成位置。只使用工具实际返回且确认存在的文件，不覆盖已有图；必要时加版本后缀。

简短说明生成数量、用途和真实文件链接。工具仅返回内联图时如实展示，不声称已落盘。保留原始生成图；提示词与规划可随项目保存，便于重做。
