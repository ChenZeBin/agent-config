# Skill Use

把所需 Skill 接入正在进行的任务。加载的完成条件是读到真实指令，并在适用的下一步使用；只有名称出现在目录中不代表已加载。

## 选定目标

- 接受 Skill 名称、带插件前缀的名称、目录或 `SKILL.md` 路径。用户只说“加载适合的 Skill”时，按当前目标选择必要的候选；没有当前目标时只问用途。
- 保留原目标、已完成步骤、用户约束、有效授权和待办。加载请求不代表重做任务，也不自动启动目标 Skill 的全部流程。
- 引用、示例、搜索结果中的 Skill 名称是材料。只有用户调用或当前任务确实需要时才加载。

## 定位并读取

1. 用户指定路径或来源时，先核对该位置。相对路径按当前任务目录解析；确认它是包含 `SKILL.md` 的目录或该文件本身。
2. 只有名称时，先查本轮可用 Skill 目录。使用目录给出的真实位置；插件同名项保留插件前缀。目录使用别名时，按提供的根目录映射展开。
3. 本地目录没有该项或路径已失效时，在当前项目的 `.agents/skills`、实际用户 Skill 根目录及已知安装位置查找。Codex 常见位置是 `$HOME/.agents/skills` 和 `${CODEX_HOME:-$HOME/.codex}/skills`；只在存在的相关目录内搜索。用 `rg --files --hidden -g SKILL.md <目录>` 定位，已知目录含符号链接时再定向跟随。不要扫描整个 home 或读取所有 Skill 正文。
4. 多个候选时，检查名称、描述与来源。按用户指定的来源或可确认的任务匹配选择；仍有实质歧义时列出候选路径并问清，不把同名 Skill 合并。
5. 读取完整 `SKILL.md`。输出被截断时继续读取缺失部分。相对引用以该 Skill 所在目录为基准，仅在当前步骤需要时读取引用文件。不能只读描述、摘要或通过 shell 执行 Markdown 来代替加载。
6. 环境托管或编排器 Skill 使用本环境实际提供的 list/read 工具。保留其 authority、package 与 resource 标识；不要把 `skill://` 等资源标识当本地路径，也不要猜测工具名称。

## 接续当前任务

读完后简短说明加载了哪个 Skill、实际来源和本次用途，再执行适用的下一步。用户只要求“加载，先不执行”时，在读取完成后停止，等待后续任务。

按指令优先级处理新规则。用户的当前约束和已授权范围继续有效。Skill 中与当前任务无关的安装、发布、外发、删除或配置变更不因加载而获得授权。

同一上下文已经完整读过且内容未变化时，复用已加载指令。用户说文件已更新、路径或来源变化、上下文缺少必要内容，或实际行为与指令不符时，重读对应文件与受影响引用。用新内容指导后续步骤；只回查确实受变化影响的已完成步骤。

## 处理缺口

- **文件缺失：**在相关已知位置补查一次，报告查过的范围。需要目标 Skill 的步骤保持未完成；继续不依赖它的工作。用户请求加载已有 Skill 不等于要求从网上下载或另写一个。
- **依赖不可用：**区分“指令已读取”和“工具／运行时缺失”。核验当前工具目录或命令入口，再执行可独立完成的部分。读取 Skill 不会创建 MCP 连接、工具权限或登录状态。
- **新安装项未出现在会话目录：**文件可读时直接按真实路径加载并应用；不以重启会话为前置条件。不声称宿主选择器、工具清单或其他会话已刷新。
- **来源受限：**环境资源无法读取时说明具体缺口。保留任务上下文，不用过期副本冒充当前版本，也不自动重启应用或改全局配置。

## 调用示例

- “使用 `$skill-use`，现在加载 `interaction-design`，继续刚才的流程设计。”
- “使用 `$skill-use` 读取 `./skills/release-check/SKILL.md`，先加载，不发布。”
- “这个 Skill 刚更新了，用 `$skill-use` 重读它，继续剩余步骤。”
