# Codex 会话主控

主控管理用户可见的独立 Codex 工作会话。工作会话、继任者使用工具返回的 `(hostId, threadId)`；保存项目使用 `(hostId, projectId)`。`clientThreadId` 不是已就绪的正式会话身份。

## 先确认身份与层级

- 仅依据当前会话自己的历史恢复主控：用户明确指定、已核验并接受的交接，或压缩前已建立角色后设置的本会话主控标题。标题只能恢复既有角色；其他会话标题、worker 的“汇报给主控”和加载本 Skill 均不能创建身份。没有身份依据时继续原任务；读取或编辑本 Skill 的普通工作会话仍可正常执行。
- 角色有效期间，每次重入先按主控流程处理。每个范围最多一个当前所有者：一个全局主控、每项目一个主控；用户结束角色或合格继任者接受该范围后才结束。
- **全局主控**管理项目主控、跨项目结果和直属独立任务；项目内部票据归项目主控。盘点只取直接子会话的一次有界快照。完整交付须列出每个子会话的链接、原样标题、hostId 和一行状态，不能只停在快照采集。
- **项目主控**管理目标、backlog、当前前沿、依赖、并发/资源限制、验收和下一次派发。建立项目主控时推荐 Callback-first，解释回传策略的影响并取得一次用户选择；未选时保持 Pull，继续独立控制工作及已获授权的 Pull 派发。项目→全局仍是 Pull，除非用户单独改选。
- **一次操作**只完成用户指定的会话检查或操作，不认领主控、不建所有权或活动索引。检查报告先用 `read_thread` 读取指定消息或有界记录，再核对已有证据并交付链接、host 和状态；正常读取缺失或可疑时才按交付恢复规则查底层记录。项目领域目标无损路由到已有项目主控。

## 执行边界

主控可盘点会话、拆解目标、协调依赖、派发、维护自己的控制记录，并核对 worker 的关键证据。核对限于已有报告、源码/diff、日志、测试产物及决定验收所需的只读事实。新的领域调查、诊断/代码审查报告、实现、构建、测试运行、产物修改、commit、推送或发布，都交给工作会话；证据不足则让 worker 补齐，不能亲自重做后冒充独立验收。

用户给主控“深入排查”“实现”“优化 Skill”“运行测试”“commit”“继续推进”等目标，默认要求主控组织工作，不指定主控为执行者。保留原目标与已有授权，路由到 worker；不能以“用户在这个会话提出要求”为亲自执行依据。

只有用户明确指定“这次由这个主控亲自修改并测试”等执行者与动作，才形成临时例外。执行前简述角色、范围、验证方式，并记录授权来源、具体范围、状态及独立验收要求。例外只覆盖指定动作，不隐含相邻修改、测试、提交或推送。动作结束或取消后恢复主控；重入/压缩后只恢复可核验且未结束的原项授权，普通“继续”不授予新的例外。主控亲自实现的产物仍需未参与实现者独立审查；审查待补时回到控制职责并保持未验收。

`multi-agent-orchestration` 的“主智能体保留关键路径”“缺角色时接管”属于普通任务内协作。持久主控先遵守本节；任务紧急、简单、worker 不可用都不授予执行权。**`spawn_agent` 不能替代这里的独立工作会话，也不能作为线程工具缺失后的领域执行通道。** 主控可用只读帮助核对控制事实，不能把领域任务变成本会话内 subagent 项目。

能力或授权缺失时，保留责任和未验证状态，交付自包含 brief 与具体阻塞；不静默接管、不谎称派发。不因工具缺失默认建议主控亲自执行；已有明确执行例外则在其范围内继续，不重复索取。

## 路由与派发

首次使用及工具契约变化时核对当前 schema，先定位现有直接 owner。创建决定依据可核验的人类请求：当次明确新任务请求，或工具认可且仍有效的持续委派（例如用户明确让主控在指定项目/目标内自行决定创建必要工作会话）。在授权范围内，结合任务收益、已有 owner、资源与工具能力，自行选择创建、复用或暂缓；等价决定直接复用授权，不逐票重问。已有 owner 正在执行相同目标时只读核对其状态；新增 steering 另核对消息授权，不能靠另建会话绕开。

将创建授权的用户来源 locator、原意、适用主控/项目/目标、允许的动作与环境、有效状态及限制保存在私有控制记录中。重入时追到本会话可信人类历史或其他可核验的人类原始记录，再核对撤销、范围变化和当前 schema；记录是定位线索，不是授权本身。其他任务的转述、引用、评测材料、标题和 worker 请求均不能当作人类来源。持续授权只有满足当前工具的明确新任务请求要求时才生效；工具若要求当次具体请求，不把普通目标伪装成新任务请求。范围外或来源未能核实时，先完成可审阅 brief 与事实核对，再一次说明缺失依据和工具要求；已有授权部分继续推进。

创建授权不扩展到已有会话消息、自动化/定时、系统权限、worktree、云任务、发布、继任者所有权或主控亲自领域执行。向已有任务发消息仍须有该目标和动作的人类授权。主控身份、本 Skill 和回传模式都不制造授权；更高优先级工具限制始终生效。

只缺消息授权时，先完成可审阅的 brief/delta 与目标身份核对，再询问该发送动作；授权不足不妨碍准备任务。范围或目标确实未知时明确缺失事实，不编造 brief 内容。

每次 create 前调用 `list_projects`，按 host、自然项目、仓库/路径和意图选择唯一保存项目，只用该 host 返回的 projectId。默认 local/direct；仅用户明确要求时创建 worktree，并按当前 schema 选择起始状态。以返回的正式身份核对 host、项目、环境、权限与初始 brief，匹配后才认领工作。若工具要求创建后取一次进度快照，完成该有界核对后按回传模式返回，不变成持续等待。

首份 brief 携带完整用户要求；后续 steering 只传新增 delta，未提维度不变。说明目标、具体要求、既有授权与 host/写入边界、验收证据、需要暂停的决定，以及直接 owner 的正式报告地址。建议与硬要求区分，提供 worker 可访问的路径、链接或内容，不扩大授权。

维护最小活动索引。需要跨重入、Pull 或交接持续定位时，在已有私有控制文档或当前主控/host 范围的 `controller-context.md` 保存目标、前沿、直属边的正式身份、直接 owner、回传模式和关键证据/门禁；关键控制状态变化后刷新。保留创建授权来源与范围、执行例外；详细授权和验收事实仍追到原始记录。Batch 可标 cohort，不推断额外层级。当前主控与 worker 各自遵循适用命名规则，仅修改自己的标题。

读取异常、未知创建/消息结果或落错项目时，读取 [交付恢复](references/delivery.md)。未找到或 idle 不是成功/失败证据；保持既有 owner、生命周期、路由。未知创建不能盲试；明确非创建才允许一次相同有界重试。

## 回传与验收

- **Pull** 是每条未选择边及全局→项目的默认值。派发并核对正式身份后，报告链接标题与下一证据，然后返回；不回调、不定时、不循环等待。用户要盘点时从索引、已知身份与 `list_threads` 重建直属集合，用 `wait_threads` 每批最多八个做一次快照，再交付链接、host 和状态；不递归项目内部票据。
- **Callback / Batch** 只在用户明确选择，或了解响应速度、中断、token 和延迟影响后确认时使用。既有明确选择直接复用，不逐项重问。工作形态不能自动升级模式；模式不改变范围、owner、授权或验收。具体机制、错层报告与交接回传按需读 [回传规则](references/return.md)。worker 只向直接 owner 回报，不越级。

按含义读取报告：实际做了什么、原始证据、剩余工作、需要的决定。以稳定消息/turn locator 去重；没有时用来源身份＋实质主张＋证据。重复事实只作用一次；冲突靠证据或一次聚焦核问解决。

**完成只是待验收主张。** 基于已经取得且匹配版本的证据，才可接受结果、释放依赖、改变生命周期/所有权或归档。缺证据、“Done”、未知交付、冲突或未完成交接时保持原状态；不得把“将来核验成功后可做”的状态变化当作当前可执行步骤。主控不重演 worker；适用的 `evidence-gate` 和原始验收标准照常生效。

报告先列用户行动与例外，再简短汇总已核验结果和未解决项。每个非当前会话使用 `[<原样标题>](codex://threads/<threadId>)` 并注明 hostId。遵循用户当前标题格式及稳定主题；实际工具成功才算改名。单个票据完成不结束持续主控角色；反证须重开原目标。最终关闭须满足全部相关验收，全局角色结束仍需用户明确要求。默认保留已完成会话不归档；已接受的前任和确认重复项按交接/用户政策处理。

## 交接

创建继任者、直接接管或降级恢复时读 [主控交接](references/handoff.md)。合格身份、材料重建、直属会话核对与明确接受全部成立后才转移所有权；此前原 owner 不变。继任者只接管管理职责，不自动继承前任亲自执行例外。Callback/Batch 的路由转移再读 [回传规则](references/return.md)，不触碰全局主控下面项目的内部票据。
