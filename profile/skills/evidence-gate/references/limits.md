# 边界与故障处理

本工具降低执行时漏检和过早交付的概率，不保证所有模型、平台与任务永不出错。

联网证据由合同 `network_checks` 指向的真实 checks 采集，独立审查负责原始日志与语义核验。审查器断网和原始请求失败是不同事实；前者不能单独否定有效观测。有效期从请求所在检查开始计算，在每次 verify 重新检查；它限制证据年龄，不证明远端持续不变，也不证明脚本没有读取缓存。目标与实际响应仍需独立审查；网络错误、旧日志、手写 receipt、错误目标和冲突证据不能因此获得放行。用户明确的独立联网身份或持续监控要求不能转移。

当前本机 Codex 0.153.4 会将 exec_command 归一为 `Bash`，且只传 `command`，丢弃 workdir；不能由 Hook 恢复此字段。因此原生 Bash 的 Git 交付必须显式使用 `git -C <绝对目录>`，首个 -C 必须为绝对目录，后续 -C 按 Git 顺序解析，最终目标须精确匹配合同 root。无锚点时即使会话 cwd 与 root 相同也拒绝；不把会话目录当作丢失参数的证明。其他发布工具仍仅按宿主提供的 cwd 检查，不能声称已解决宿主遗漏目录参数的所有工具路径。

- **触发范围**：只检查已登记、同 session 的任务。未登记任务不能被程序推断成受保护；常驻指令负责要求登记。PreToolUse 将命令实际执行目录与登记 root 比较，避免换目录误用结果：仅 `exec_command` / `functions.exec_command` 的非空绝对 `workdir` 可覆盖宿主 `cwd`，省略或 null 使用 `cwd`；相对路径、无效值、非目录和不匹配目录拒绝，无关工具的同名字段不参与覆盖。Stop / update_goal 没有命令执行目录，只核验同 session 当前合同及其证据，仍须 completion 已通过且 goal_complete 为 true 才能宣称完成。
- **内容绑定**：合同、runner 与审查规则、声明的输入/产物、导入证据、真实检查日志、审查原始输出都会重新计算摘要。声明范围涉及 cwd 所在 Git 仓库时，还检查相对登记时 HEAD 的改动，未纳入范围的新改动使验收失效；登记时已有且未改变的用户 diff 不被强制纳入。`pre_delivery` 唯一例外是已结构化声明的 `post_delivery_verification.steps.outputs`：它们可以在交付后、阶段转移前出现，不能授权命令或放行完成；转移时必须已存在，并作为下一合同的 artifact 且被 criterion 引用。若它同时是前置 artifact，必须先转移再覆盖它，否则旧快照失效。纯全局配置任务不取得无关 cwd 仓库的所有权。其他仓库和 Git 忽略的文件须显式声明。
- **视觉证据**：导入文件不证明实际窗口/版本/尺寸正确。模型视觉审查仍可能误判；重要审美决策需用户看最终环境。不能声称 schema 或哈希验证了美观。
- **Stop**：Codex 的 Stop hook 只能触发额外一轮提醒，不能撤回已经显示的完成声明。本实现对每个完成候选作局部判断，排除引用、定义、否定、问句及配对条件说明；任一未被排除的完成声明都触发检查。旧记录中的 `unverified` 或另一句“未完成”不能掩盖本次完成声明。“只有…才…”按条件处理，“只有一个任务已完成”仍是完成陈述。到达一次续跑上限仅提示未验收，状态不变成 accepted。措辞检测是有限语法启发式，可能遗漏或误报，不是完整的自然语言理解或真实性安全机制；确定性的交付门禁以 verify/PreToolUse 状态为准。
- **局部否定**：任务状态候选使用明确句式，不使用跨主语的任意字符匹配。否定助动词与程度词按组合规则识别，关系否定仅作用当前有界分句且不跨“但/却/而”等转折，支持“没有完成”“尚未全部完成”“不等于所有工作已完成”和“不能声称已完成”。定义谓词可带“只/仅”等限制词；“已完成，说明…”中的逗号不被吞掉，仍视为声明。一处否定不能放行另一处独立声明；也不把“本次任务检查通过”直接当作任务完成。这仍不是任意语言、嵌套语义或所有表述的完整解析。
- **PreToolUse**：只识别 Bash 中直接出现的 `git commit/push/tag`、`gh pr create/merge`、`gh release create`、`npm publish`、`cargo publish`、`twine upload`，以及 `update_goal` 的 complete。completion 阶段的交付动作要求 `accepted` 且 `goal_complete: true`。`pre_delivery` 的 `accepted` 只放行合同 `deferred_actions.approved_commands` 中逐字符精确匹配的交付命令；未声明动作、命令变体与 `update_goal complete` 均拒绝，随后仍执行相同的 shell、范围和 Git 暂存核验。复合 shell、重定向、命令替换及环境覆盖拒绝。Git commit 要求暂存集合在合同内，且暂存内容与已审查工作区一致；不支持 `commit -a`、pathspec 和未列入白名单的选项，应先单独暂存再提交。Git push 只检查当前任务证据，**不证明推送的 refs/历史只包含本次任务**，仍需在授权范围内检查待推送提交。别名、包装脚本、MCP 专用发布工具、已有 `write_stdin` 会话等不完整覆盖。只能称为常见路径拦截。
- **信任与故障**：未信任/已修改的 Hook 会被 Codex 跳过；必须在 Codex `/hooks` 或产品提供的 Hook 界面查看实际状态并显式信任。仅有 `hooks.json` 不等于生效。本脚本内部异常按未验收返回；Python 不存在、Hook 超时或 Codex 不运行 Hook 等宿主故障仍可能绕过，应查看宿主记录。
- **权限**：同用户权限可以改合同、脚本、凭据或关闭 Hook；状态摘要不是签名。本地验收不能充当恶意执行者不可绕过的发布安全边界。更强边界需要受保护的 CI、独立凭据和分支保护，须另行授权配置。
- **语法解析**：使用随包的 [bashlex](https://github.com/idank/bashlex) 0.18 语法树识别实际 command 节点，覆盖条件、循环、分组、注释及换行；已支持的 quoted word 和 here-doc 数据不作为 command 节点。仅对单个静态 word 的原始切片用 shlex 还原普通引号/转义拼接，保留单引号数据中的换行，不求值动态部分。检测和 Git 暂存检查共用这份字面量。算术展开等不支持的语法回退到保留原始拼写的词法扫描，按控制分隔符后的命令位置检查，而不扫描 echo/printf 的参数；不把引号中的分号当分隔符。回退不能完整理解 here-doc 等全部 shell 语法，可能误报；词法本身也无法解析时保守拒绝。它不执行命令、不读取包装脚本、不展开动态变量、glob、brace 或 tilde，不是全 shell 语义解释器。依赖缺失时已登记任务的工具检查按失败处理；普通答复不依赖它。
- **命令参数**：检测和 Git 暂存校验共用字面量 `command --` / `command -p` 解析；`command -v/-V` 仅查询，不当作执行。已知全局选项按是否带值解析，包括 npm `--loglevel info` 和 Cargo `--color never`。未知选项按可能带零个或一个值保守识别，疑似交付时要求验收；即便已验收，仍拒绝不确定的选项参数形式，可改用明确的 `--key=value`。因此未知选项的值恰好是交付词时可能误报。`env` 包装在交付时拒绝，不能借包装绕过 Git 暂存检查。参数依据：[npm 配置](https://docs.npmjs.com/cli/v11/using-npm/config/#command-line-flags)、[Cargo 参数](https://doc.rust-lang.org/cargo/commands/cargo.html#options)。
- **特殊引号**：bashlex 没有展开 ANSI-C `$'…'` 或本地化 `$"…"` 单词，不能把其 `word` 当作最终参数。本实现发现受保护工具、包装命令或可执行词使用这些语法时保守拒绝，即便已经验收也要求改用普通字面量；这可能拒绝只读 Git 命令的特殊引号参数。普通 `echo` / `printf` 中的数据不会据此变成交付动作。它没有执行待检查文本来求值。
- **未支持的关键字**：已对随包解析器未实现的 `time`、`coproc`、`select`、`case`、算术 for、条件表达式增加命令位置正反例。`time` 的后续工具参与检测，`-p` 与常见带值参数不会遮蔽它；递归计时前缀后的分组与 `!` 仍按管道结构检测，不把 printf 参数中的这些字符当作结构。计时或协程包装不是验收后的放行交付路径，交付仍要求独立 simple command。回退不是完整的所有 shell 方言解释器。
- **用途与状态定义**：明确的“用于/用来 + 判断/检测/表示/记录”等用途补语，以及紧邻定义谓词的“已完成状态只表示…”属于解释，不当作当前断言；裸“判断结果表明任务已完成”“当前任务进入已完成状态”仍接受门禁检查。这些排除仅作用当前候选，后续独立完成断言不会被掩盖。复杂嵌套与隐含指代仍属于有限措辞检测的边界。
- **语句类别**：定义谓词也识别“通常/一般/往往”等限定语；禁止声称的否定形式包括“不要/请勿/禁止”。明确验收声明可独立成行，也可接逗号及后续分句，如“验收通过，可以交付”。同一句式在缺少语境时可能同时具有解释和断言含义，因此有限启发式不能承诺消除所有漏报或误报；它不能替代结构化验收状态。
- **隐私**：独立 Codex 审查会读取声明的项目文件和验收日志，使用本机配置的模型服务。不要登记秘密、认证目录或无关个人数据；检查日志也应避免输出凭据。

需要卸载时，只移除 `hooks.json` 中命令指向本 Skill 的条目以及全局 AGENTS 的“证据验收”短节；不删除其他 Hook、Skill 或项目文件。保留状态记录供审计。回滚安装配置可使用安装报告中记录的备份。
