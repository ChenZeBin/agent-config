# 移动 App 真机运行

默认使用命令行完成编译、安装和启动。按平台只读取需要的参考文件：

- iOS：[iOS 流程](references/ios.md)。需要完整 Xcode 工具链，不要求打开 Xcode 界面。
- Android：[Android 流程](references/android.md)。使用项目的 Gradle Wrapper、兼容 JDK 和 Android SDK，不要求打开 Android Studio。

项目自己的构建脚本、Scheme、模块、变体和包名放在项目中维护。复用已核验的项目入口，不把某个项目的参数写成通用默认值。混合仓库先根据任务选定客户端；跨平台框架先沿用其项目构建入口，再按对应平台核验设备与运行产物。

## 执行

1. 明确项目、目标 App、构建配置和目标设备。日常开发使用 Debug；用户明确指定的目标优先。设备名只用于定位，实际操作绑定 iOS UDID 或 Android serial。缺少目标信息时先查项目及本机私有配置。
2. 核对工具版本、签名或安装条件、设备连接与授权状态。依赖不可用时记录阻塞，继续可独立完成的源码或构建检查。条件已具备但尚未构建时，直接进入构建；未执行的步骤不等于阻塞。不要自行改用另一台设备。
3. 构建当前源码。记录源码版本及未提交状态、命令、退出码和产物位置。保留增量缓存，不把 Clean、删除缓存或改变永久构建参数当作常规步骤。命令行主要减少 IDE 开销，不保证编译加速。
4. 核对产物的 Debug 配置和 App 身份，再安装到指定真机并启动。每一步成功后才进入下一步。安装或启动失败时先诊断，不自动卸载、清除 App 数据或把旧安装当作新构建。
5. 分别核验构建、安装、启动和用户要求的功能。退出码、安装成功或进程存在不能替代前台 App 和目标功能的观察。没有界面观察工具时，准确报告已验证步骤和未验证范围。

不默认连接调试器、启用断点、开启持续控制台或采集完整运行日志。保留编译错误；失败时按需读取有限诊断信息。降低输出量不能隐藏失败。

## 测试与交付

遵循当前适用的 `evidence-gate` 和设备规则。端到端测试前，先按用户需求生成用例并完成独立 `plan-review`；未通过时继续静态检查和环境准备，不能先执行受影响测试。普通源码检查不自动升级为端到端测试。

交付说明实际设备、构建配置、源码与产物、安装和启动结果、功能观察及未覆盖项。用例失败、跳过、阻塞或缺证据时不得宣称完整验收通过。签名、配对、登录或权限问题只阻塞依赖该条件的步骤。

需要 IDE 专有功能时再打开 IDE。商店分发、TestFlight、发布签名等请求转入对应发布流程；本 Skill 不以安装成功代替发布完成。
