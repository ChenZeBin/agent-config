# 场景对照：同一原则，不同解法

以下均为假设设计示例，不是已实现功能、实测结论或指定样式。只借用推理方式，不复制布局。

## 剪贴板历史：高频找回，结束后继续原任务

场景：写作时找回刚才复制的一句话，库中有多条相似记录。

阻力不是缺一个详情页，而是辨认目标和切回工作。可以比较：完整历史窗口（有利长文阅读与管理）、紧凑列表面板（快速复用）、横向内容卡片（预览更丰富但列表扫描和键盘定位可能更费力）。若高频短文本找回占主导，推荐紧凑面板并保留可发现的入口和完整历史窗口。

候选路径：唤出后焦点在搜索 → 最近记录有明确选择 → 搜索显示命中附近片段以区分相似项 → 回车复制 → 复制成功才收起并尝试恢复原上下文；Esc 取消不改剪贴板。明确“复制”与“直接粘贴”是不同动作，不暗中获取辅助功能权限或承诺目标应用接收成功。

无结果保留查询与清除入口；长文字有展开路径，复制完整原文；失败时保留面板和选中内容。使用内容层级和低噪声选中态建立视觉秩序，来源/时间辅助辨认。链接预览可用本地解析，不自动把剪贴板上传或抓取链接。

验证：给相似开头、正文后部命中、长文本和旧记录，观察找对与回到原任务，而非只演示第一条记录。产品若主要用于长文归档，对照阅读可能应成为主界面。

## 转账提交：正确、可核对、结果可信

场景：向一个新收款人转账，服务响应可能超时。仅作交互示例，不作财务或合规建议。

减少无意义重输，但保留关键收款信息与金额核对。评估一个清楚的审阅面是否比压成“一键转账”更容易防错。提交后即时表示已收到动作，不立刻显示转账成功；结果未知时明确提示并提供状态查询，避免诱导再次提交。真实后端能防重复才可声称重试安全。

不能撤销已完成转账时明确边界，提供实际可用的下一步，不设计虚假的撤销按钮。视觉优先突出核对字段、当前状态与可采取的行动；成功反馈克制。验证应包含理解测试、输错对象、超时与离开后返回，而不是只比较点击数。

## 阅读与研究：允许慢，保护理解与定位

场景：阅读长文、比较两份材料、摘录后回到原段落。

可考虑保留位置的阅读面、并排比较或渐进展开，取舍是注意力、屏幕空间和同时可见的信息量。不要套用“取用后立刻关闭”，也不以阅读时长降低为成功。清晰排版、出处、标注与返回位置比炫目的转场更关键。

验证同一段材料的理解、跨文比较和重返原位置，另收集舒适度与偏好；用户停留长可能是投入，也可能迷失，需结合行为解释。

## 有边界的修改：不要借小修推翻系统

用户只要求导出按钮文案与反馈时，检查导出的对象、范围、等待与完成语义，给出最小改动。没有证据不宣称现有架构错误，不为展示完整方法添加侧栏、引导页或全局重设计。具体颜色与字号若沿用既有系统即可满足，就不另造品牌。
