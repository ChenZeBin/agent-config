# 交互体验设计

把抽象的“好用、有质感”转成有理由、可执行、可检验的体验选择。平台一致性是约束与资源，不能替代对用户任务的判断。以下是设计启发式，不是经过本 Skill 证明的普遍心理定律。

## 先判定要解决多大的问题

- 概念解释：回答共性与适用反例，不强迫进入产品设计或文件修改。
- 局部改进：只分析受到影响的路径，给最小修正及验证；不扩成全产品改版。
- 核心流程或新产品：建立体验主线，比较实质不同的交互结构，再推荐方向。
- 审查：保持只读，区分已观察问题、由材料推断的风险和未验证机会。
- 实现：在用户已授权范围内把选定方案转成代码与实际交互验证；设计建议不自动授权重构、发布、采集行为数据或联网处理用户内容。

先读用户提供的界面、流程、代码或研究中最影响决策的材料。没有材料就标注假设；不要捏造访谈、竞品观察、运行行为或转化数据。只有缺失信息会改变方向时才提问，否则带着明确假设继续。

macOS 原生设计/实现需要平台能力时，配合可用的 `design-macos-apps`：本 Skill 决定任务、流程与体验取舍，平台 Skill 决定窗口、命令、输入、系统行为及其验收。其他平台同理。无需为了概念讨论加载完整平台验收流程；具体实现仍遵守适用的平台合同。平台 Skill 不可用时可继续概念设计，标明平台映射待核验。

## 找出值得打磨的体验主线

用一句可观察的场景描述代替功能清单：**谁，在什么处境与触发下，要从什么状态到达什么结果；结束后继续做什么。** 补充最重要的限制：使用频率、经验、设备/输入、注意力、数据规模、延迟与失误后果。把已知事实和假设分开。

按场景选择主目标：快速完成、正确与信任、探索与理解、创作掌控等；允许兼有，说明冲突时谁优先。减少总负担，包括理解、决定、执行、等待、恢复与上下文切换，不把“点击更少”当成唯一指标。

当方向尚未确定时，比较少量真正不同的流程/信息组织：分别适合谁、优点、代价与放弃什么。颜色、圆角变化不算独立交互方向。已有明确约束或微调任务不强凑备选。

## 用共性作诊断，输出具体决定

只展开当前任务相关项。每个重点落到 **场景中的阻力 → 设计决定 → 代价/例外 → 验证方法**；不输出一张全勾选的原则清单。

涉及剪贴板等私人内容时，优先在本地解析与呈现；不得把内容自动上传，也不得自动抓取剪贴板中的链接。若确需联网处理，先让用户明确选择并说明发送范围。

| 共性 | 需要作出的决定 | 必须考虑的反例 |
| --- | --- | --- |
| 意图与主次清楚 | 首屏和默认焦点帮助谁完成什么；频繁行动与管理功能如何分层 | 低频用户需要发现入口，不能只剩隐藏快捷键 |
| 识别胜过回忆负担 | 用哪些内容线索、预览、相似项差异、命中上下文帮助辨认 | 完整详情与精确信息不能被漂亮摘要替代；敏感预览可需遮蔽 |
| 状态与因果可理解 | 操作发生在哪里、作用于什么、何时算成功、等待中能做什么 | 点击后的动画不能冒充远端完成；超时可能是结果未知 |
| 行动与上下文连贯 | 进入、选择、提交、退出/继续工作的路径，焦点与临时状态如何保留 | 需要持续阅读/对比时，不应为省空间让内容频繁消失 |
| 用户保有控制权 | 取消、撤销、恢复或不可逆前的审阅；默认行为是否可预期 | 高后果动作值得增加核对；无法撤回的行为不可承诺撤销 |
| 熟练度与能力包容 | 可见入口与适合平台的加速路径共享同一语义，支持键盘/辅助技术等必要替代 | 不强制手势、悬停、颜色或记忆快捷键作为唯一入口 |
| 反馈有节奏与分寸 | 即时响应、真实进度、局部错误和完成反馈如何分工 | 不用庆祝动画、打断通知和固定时长装饰拖慢高频任务 |

用一条具体路径说明触发、输入/选择、动作语义、可见反馈、后续去向。覆盖最影响该任务的异常，例如无结果、长等待、拒绝权限、失败或中断后恢复；按风险选，不强制所有状态。异步操作明确区分未开始、进行中、已成功、已失败、结果未知；仅在相关时定义重复提交、取消和重试行为。

## 把辨识度建立在产品行为上

选一个值得记住的体验时刻：快速找回、清楚比较、放心提交、顺手改错、沉浸阅读等。说明它服务什么情境、依赖什么、失败时怎样。新奇是候选手段，不能牺牲可理解性、可访问性和控制感。

为这一时刻选择一致的视觉表达：内容层级、排版与密度、颜色语义、空间关系和动效作用。用真实复杂度的内容推演，避免只有整齐假数据时好看。保留用户品牌约束；方向开放时探索不同视觉性格并说明适合哪种内容与节奏，不把极简、卡片、玻璃、渐变或大留白当通用答案。

给出具体的视觉决定及理由，而不只说“高级、克制”。动效表达状态变化或空间关系，提供适用的减少动态效果方案，不靠强制动画时长塑造质感。

需要完整例子或检查是否把剪贴板模式泛化时，读 [场景对照](references/scenarios.md)。

## 用行为证据校准判断

为最重要的设计假设选可观察的任务和失败信号。验证方案使用相同任务、相当的数据难度与输入条件，区分新手/熟练者；比较多方案时注意顺序和学习效应。

比较两个交互方向时，把推荐方案和一个实质不同的备选做成可执行原型对照：说明参与者、相同任务与输入、顺序如何平衡、记录哪些成功和失败信号，以及据什么结果决定保留或调整方案。没有实测数据时，把判定规则写作待验证假设，不编造成功率或用户偏好。

快速工具看找对率、找回时间、误操作和回到原任务的连贯性；高后果操作看理解、正确性、重复提交和恢复；探索/创作看定位、理解、比较与重返上下文。不要套同一速度指标。指标目标若未测量，只能写为候选目标，不能捏造提升百分比。

原型走查帮助暴露流程问题；真实用户任务观察才提供可用性证据；偏好与情感反馈是另一类证据。模型审查、截图、代码检查和自动测试均不能单独证明“用户喜欢”或“眼前一亮”。没有真人测试也可以交付方案，清楚标记设计假设与下一步验证即可。

## 交付与停止

默认交付紧凑的决策说明：推荐体验与原因、关键流程、有关的异常/恢复、视觉辨识度、代价与验证。随任务深度裁剪，不固定输出章节、表格或字数。实现规格另补必要状态、命令语义与验收条件。

检查：建议是否改变了真实操作，而非只是更换形容词？是否尊重产品目标和局部范围？是否保留适当控制？是否说明关键取舍？证据是否支持所称结论？这些问题可回答后就交付，不无限扩大调研或阻塞在理想证据上。
