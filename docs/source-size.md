# Source-size guard

The default limit is 20,000 bytes per hand-authored source file. This is roughly
5,000 tokens at bytes / 4, not a tokenizer measurement or a performance claim.
File size is a guardrail, not a substitute for cohesion, complexity checks or tests.

## Check and install

```sh
python3 -B scripts/source_size.py --staged
python3 -B scripts/source_size.py --tree HEAD
python3 -B scripts/source_size_hooks.py install --scope global
python3 -B scripts/source_size_hooks.py install --scope local --repo .
```

The checker reads complete Git blobs and policy from the index in staged mode.
It does not read the working-tree content of a staged file. Deleted files are
ignored. Renames are checked at their new path. In tree mode it checks every
source file in the selected commit/tree. An empty initial index passes.

Source types include common programming languages, stylesheets, SQL and
extensionless shebang scripts. Lockfiles and non-source assets are excluded.
Symlinks and submodules are not followed. Handwritten tests and CSS are checked.
The checker does not infer whether a human or an agent authored a file.

## Exceptions and existing files

Commit `.source-size.json` with this structure when exceptions are necessary:

```json
{
  "version": 1,
  "generated": [
    {"path": "src/api/schema.generated.ts", "reason": "Generated by the API schema compiler"}
  ],
  "baseline": {
    "src/legacy.py": {"max_bytes": 24000, "reason": "Pre-existing parser; split before any growth"}
  }
}
```

Generated paths require exact, case-sensitive repository-relative POSIX paths
with reasons. Wildcards are rejected, including generated/vendor directory
patterns. They are reviewable exemptions, not automatic author detection.
Never exempt all source or all tests. Baselines require exact paths and a byte ceiling above the
default. A rename does not inherit an old path's baseline. A reduced baseline
should be updated after a refactor. Do not raise it to make a change pass.

`python3 -B scripts/source_size.py --baseline` prints a proposal from HEAD. Review
it before saving. The tool never writes policy or baselines on its own. This
repository keeps explicit ceilings for existing files rather than rewriting
unrelated skills while installing the guard.

When a check fails: find responsibility boundaries, extract cohesive modules,
keep public interfaces stable, update imports, run relevant tests, stage all
changed modules and retry. Do not minify, add forwarding shells, duplicate code
or create circular dependencies just to pass the size check.

## Hook compatibility and recovery

The optional installer copies only the checker/dispatcher to
`~/.local/share/agent-config/source-size/`. It does not link a full profile or
change Codex trust, credentials or other repositories' configuration.

Global installation supplies the default hooksPath. It refuses an unknown
existing global hooksPath. Its dispatchers preserve executable `.git/hooks/`
hooks, including commit-msg and pre-push, with their arguments, stdin and exit
status. Git ignores non-executable hooks in the same way it normally does.
Default-hook lookup uses Git's exported directory paths, including a linked
worktree's common directory. It does not require a usable HEAD during the
initial reference transaction of `git init`.

A repository's local hooksPath overrides the global default. Install locally in
that repository to chain the previously configured path. The installer does not
scan or mutate other projects. The default global installation alone therefore
does not guarantee enforcement in every existing repository.

The native `.githooks/pre-commit` in this repository also calls the same checker
before its original validation/privacy/Gitleaks checks. Only the size check is
index-only; the existing full validation keeps its original scope.

```sh
python3 -B scripts/source_size_hooks.py uninstall --scope local --repo .
python3 -B scripts/source_size_hooks.py uninstall --scope global
```

Uninstall restores the prior hooksPath setting. It keeps dispatcher/runtime
files for inspection and recovery; it never deletes or rewrites original hooks.
Local wrappers reference a shared runtime. Keep that runtime while any local
wrapper is active. A changed configuration or unknown file collision causes a
nonzero exit rather than an overwrite.

Runtime updates are staged before switching files. If replacement raises an
I/O error, the installer restores the prior runtime and ownership record.
This is recovery from a reported update error, not a guarantee against process
termination or power loss during the switch.

Hooks can be skipped by Git options and local policies can be edited. This is
not a security boundary against a same-permission actor. Keep CI's committed-tree
check and review policy changes. Add the CI command to other projects when
adopting the guard there; this repository cannot change their workflows.
